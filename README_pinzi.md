## 与 `/hanzi` 的区别（重要）

两门课**不是同一种视频**，播放器针对性做了不同取舍：

| 维度 | `/hanzi`《汉字是画出来的》 | `/pinzi`《汉字是拼出来的》 |
|---|---|---|
| 单集时长 | 约 30 秒 | **20~31 分钟** |
| 单集体积 | 约 1 MB | **40~80 MB** |
| 集数 / 总量 | 108 节 / 195 MB | 18 节 / 约 0.9 GB |
| 卡片封面 | 汉字大字（零加载成本） | **真实课程封面图** |
| 检索维度 | 汉字 / 拼音 / 首字母 | 课程标题关键词 |
| 步进幅度 | ±5 秒 | **±10 秒**（长课小步进效率太低） |
| 倍速 | 无 | **1 / 1.25 / 1.5 / 1.75 / 2** |
| 断点续播 | 有 | 有（长课尤其关键） |

两条链路都分离：**列表 JSON 走 FastAPI**，**视频/封面字节流走 Nginx**（`alias`，支持 `Range`）。

## 要点

- **`meta.json` 是标题的唯一真源**：课程标题如「第7讲 漂亮的姜姓女子就要出嫁了」含标点、
  可能超长，不适合直接当文件名。下载器把完整标题、封面、时长写进 `meta.json`，
  视频文件名只用序号 + 截断标题。**改标题只改 JSON，不动字节流。**
- **降级链**：`meta.json` 缺失/损坏时接口自动退回扫目录（标题取文件名 `-` 之后的部分，
  封面与时长留空），**绝不 500**。
- **课程顺序不能信接口**：`column.items.get` 传 `sort=asc` 实际返回**倒序**（总结篇在最前）。
  下载器 `course_order()` 按「先导篇 → 第1讲 … 第16讲 → 总结篇」重排，否则串讲逻辑全错。
- **`resource_type=3`**：该店把长视频标为 3（《汉字是画出来的》是 2），枚举时不能只认 2。
- **`can_view=0` 是历史字段**，不代表不可看 —— 实测全部 18 节都能取到播放地址。
- ⚠️ Nginx 屏蔽 `/pinzi/` 下 `json/py/...`（`meta.json` 含 `resource_id`），
  封面只放行 `covers/` 子目录。

## 接口速查

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/pinzi/list` | 视频列表（序号升序，含标题/封面/时长/已编码 url） |
| GET | `/pinzi/<filename>` | 视频文件（Nginx 静态，支持 Range → 206） |
| GET | `/pinzi/covers/<nnn>.jpg` | 课程封面（Nginx 静态） |
