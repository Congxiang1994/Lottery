## 0. 结论先行

「能用但不够精美」不是审美问题，是 **1 个结构级 bug 拖累了全局**，外加 3 类交互缺口和一组排版精度问题。

| 级别 | 问题 | 用户感知 |
|---|---|---|
| **P0** | 弹窗被祖先容器的 `transform` 困住 | 列表滚过一屏再点开故事 → **弹窗完全跑出视口，页面只剩一片变暗，看着像"点了没反应"** |

## 1. P0 · 结构级问题

### 1.1 弹窗被祖先 `transform` 困住（全站性，影响 3 个弹窗页）

**实测证据**

| 场景 | 测量结果 |
|---|---|
| 桌面 1280×900，列表滚到 `scrollY=1600`，点开一篇 | 面板 `top=-1489 bottom=-685` → **完全在视口外** |
| 桌面 1280×900，同一时刻 | 遮罩 `left=84 right=1196`（视口 `0→1280`）→ 左右各 84px 未覆盖 |
| 手机 390×844，滚到 `scrollY=900`，点开一篇 | 面板 `top=-791` → **在视口上方 791px**；遮罩 `top=-839` |
| `.anim-page-in` 等待 4s（动画 0.45s 早已结束） | `transform = matrix(1, 0, 0, 1, 0, 0)`　`animation-fill-mode: both` |

**根因链**

```
App.tsx:44   <div key={pageKey} className="anim-page-in">   ← 包住所有页面的容器
index.css:142 .anim-page-in { animation: page-in 0.45s … both; }
index.css:130 @keyframes page-in { to { transform: translateY(0) } }
                                  ↑
   fill-mode: both 让元素在动画结束后**永久保留** to 的关键帧值，
   而 to 的 transform 是 translateY(0)，computed 为 matrix(…)，**不是 none**。
                                  ↓
   按 CSS Transforms 规范：transform 非 none → 该元素成为
   position:fixed 后代的**包含块**。
                                  ↓
Story.tsx:531  遮罩 className="anim-overlay fixed inset-0 …"
               的 inset-0 不再相对视口，而是相对 .anim-page-in 的盒子
               （= main 内容盒，桌面 84→1196、手机 20→370，高度 = 整页内容高）。
                                  ↓
   • 遮罩左右缩进、盖不住导航栏
   • 面板固定在「文档顶部 + my-8」，页面一滚就落到视口外
```

**为什么之前没被发现**：`scrollY=0` 时面板恰好落在视口顶部附近，症状被掩盖；只有先滚动列表再点开才会暴露。

**影响面**：`/story`、`/hanzi`、`/babysong` 三个页面都用了 `fixed` 弹窗，同一个容器 → 同一 bug。`/hanzi` 实测遮罩同样落在 `84→1196`。

**修复选项**（按推荐度）

| 方案 | 改动量 | 说明 |
|---|---|---|
| A. `.anim-page-in` 的 `animation-fill-mode` 从 `both` 改成 `backwards` | **1 个词** | 动画结束即释放 `to` 值，`transform` 回到 `none`，包含块消失。视觉无变化（`translateY(0)` 本就等于原位）。**代价最低、收益最大** |
| B. 入场动画只动 `opacity`，去掉 `translateY` | 小 | 丢失位移入场感 |
| C. 所有弹窗改用 React Portal 挂到 `document.body` | 中 | 最彻底，顺带解决 z-index/层叠问题，但要改 3 个页面 |
| D. 动画结束监听 `animationend` 后手动清 `transform` | 小 | hack 味重，且 SSR / 首帧易漏 |

**推荐 A + （后续）C**：A 立刻止血；C 作为弹窗层的长期正确形态。

### 1.2 弹窗遮罩不铺满视口

同一根因（见 1.1）。修掉包含块后 `inset-0` 自然恢复全视口。

另需确认一处：`header` 是 `position:sticky; z-index:30`，遮罩是 `z-50`。修好后遮罩会盖住导航栏 —— 这是期望行为，但需要真机确认导航不会被穿透点击。

---

### 1.3 打开弹窗时背景横向跳动 5px

**实测**：打开前 `html.clientWidth=1270`（滚动条 10px）→ 打开后 `=1280`（滚动条 0）。

`Story.tsx:341` 用 `document.body.style.overflow = "hidden"` 锁背景滚动，但 **没有补偿滚动条宽度**（`body.paddingRight = 0`）。桌面上居中容器（`mx-auto max-w-6xl`）会因此整体横移约 5px —— 打开/关闭各抖一次。

**修法**：锁滚动时记下 `window.innerWidth - documentElement.clientWidth`，补到 `body.paddingRight`；或直接给遮罩层用 `overflow-y: scroll` + 固定 gutter。

---

### 1.4 手机端弹窗底栏三控件挤压换行

**实测（390×844）**

| 项 | 数值 |
|---|---|
| 面板宽 | 318px |
| 底栏可用宽 | **260px** |
| 三控件宽合计 + 2×gap(12px) | 236 + 24 = **260px** → 零余量 |
| 控件高 | 更早 **46px** / 字号组 **43px** / 更新 **46px**（单行应为 ~30px） |

→ 文字被挤到竖排两行：「更/早」「更/新」「标/准」。

**修法建议**：底栏在 `<sm` 断点改成两行布局（上一行字号档位、下一行前后篇），或把「更早/更新」收成纯图标按钮（`aria-label` 保留语义）。

## 3. P2 · 视觉精致度

### 3.1 对比度（实测 WCAG）

| 元素 | 实测 | 字号 | 要求 | 判定 |
|---|---|---|---|---|
| 页标题 | 12.48:1 | 30px | 3:1 | ✅ |
| 卡片标题 | 12.48:1 | 15.5px | 4.5:1 | ✅ |
| **副标题** | **4.17:1** | 14px | 4.5:1 | ❌ 略低 |
| **卡片摘要** | **4.17:1** | 12px | 4.5:1 | ❌ 略低 |
| 标签 | 5.39:1 | **10px** | 4.5:1 | ⚠️ 达标但字号过小 |
| **日期数字** | **2.83:1** | 22px 粗 | 3:1（大字） | ❌ 未达标 |

金色 `#c98600` 压在米白 `#faf6f1` 上只有 2.83:1 —— 这是"发灰、不够精致"的主要来源之一。

> 参考：夜间模式实测全部达标（正文 13.11:1、标题 14.59:1、摘要 6.16:1、按钮 6.16:1）。**问题集中在日间。**

### 3.2 emoji 孤儿行（17/17 篇都命中）

数据里正文段落普遍以 `" 🌱。"` 形式结尾（空格 + emoji + 句号）。中文排版下这个空格成了合法断行点 → **emoji 和句号被单独挤到下一行**。

实测出现的孤儿行：`🌱。`、`✨。`、`🌙。`

**修法**：渲染前用正则把「emoji + 紧跟的标点」包成 `<span style="white-space:nowrap">`；或把内容里的半角空格换成 word-joiner `U+2060`。列表摘要同样处理。

### 3.3 正文贴住底栏分隔线

滚动区没有渐隐遮罩，最后一行文字生硬地压在 `border-t` 上（截图可见）。加一层 `mask-image: linear-gradient(transparent, #000 12px)` 或底部 24px 渐隐白/暖黑叠层即可。

### 3.4 弹窗面板「不够纸」

`Story.tsx:538` 日间用 `.glass`（`rgba(255,255,255,.72→.5)` + `blur(14px)`）。在暖棕遮罩上呈**米白发灰**，与注释里写的"书页化排版"气质不符。睡前场景建议换成实心暖纸底（`#fffdf9 → #fbf3e7` 渐变 + 极淡纸纹），去掉玻璃感。

### 3.5 列表信息重复度高

「动物」标签 10/17 篇出现，同日多篇时日期竖块连续显示 5 个「28」。

| 问题 | 建议 |
|---|---|
| 标签碎片化：27 个不同标签，**17 个只出现 1 次** | 只展示高频主题标签（动物/勇气/安心/亲情/分享/入睡），长尾标签收进详情页 |
| 同日多篇 → 5 个相同日期 | 按日期分组，日期只出现一次（做成分组头），或组内改用序号 |
| 标题 emoji 不统一（3/17 带） | 统一策略：把 emoji 抽出来当卡片左侧的"封面图形位"，标题里剥掉 |

### 3.6 版式对齐断裂

桌面 1280 实测：导航 Logo 左边界 **64px**，页标题左边界 **256px** —— 差 192px。

原因：`App.tsx` 的 `main` 是 `max-w-6xl`(1152)，故事页内容又是 `max-w-3xl`(768) 再居中，形成双层缩进。

**建议**：给阅读类页面单独放宽到 `max-w-4xl` 并与导航左对齐（阅读宽度靠 `px` 控制而非 `max-w`），或把导航容器也收到同宽。

### 3.7 其他

- 日间卡片 hover 的 `card-hover` 上浮 4px + 金色边框，在触屏上无意义且移动端可能残留 hover 态。
- 空状态、加载态、错误态三者的视觉分量与列表卡差距大（错误块用 `rounded-2xl`，卡片用 `rounded-3xl`）。

### 过程中额外发现并修掉的一个新缺陷

滚动区最初写成 `flex-1`（`flex:1 1 0%`）+ 中间套一层 `relative` + `h-full`。实测：

```
面板 h=820（max-h 生效）
└ [2] relative min-h-0 flex-1   h=0
   └ 滚动层 h-full              h=882  ← 超出父级，被 overflow-hidden 静默裁掉
「正文 可视=882 内容=882 可滚=0」→ 底部内容看不见也滚不到
```

两个独立原因叠加：① `flex-basis:0` 在**内容驱动高度**的 flex 容器里没有正向剩余空间可分配 → 该项恒为 0；② `height:100%` 的父级 `height` 仍是 `auto` → 百分比解析不到定高，回落成内容高度。

改用 `min-h-0 flex-auto`（基准取内容高，超出时靠 `min-h-0` 收缩），渐隐改 `mask-image`。修后 5 个视口的 panel 高度均精确等于 `视口 − 80px`，且 `scrollHeight === clientHeight`（无溢出）。

### 版本控制

- 弹窗限高算式：`max-h-[calc(100dvh-5rem)]` = 视口 − 遮罩 `p-4`(2rem) − 面板 `my-6`(3rem)。**改内边距必须同步改这个算式。**
