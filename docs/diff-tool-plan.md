```
frontend/src/tools/
├── DiffTool.tsx              # 视图层：状态编排、DOM 生命周期、工具栏
└── diff/
```

## 3. 行内细粒度选推：为什么单位是「替换组」

### 3.1 直接推单个片段是错的

逐字 diff 会把 `"red"` → `"blue"` 切成：

```
del "r"  /  ins "blu"  /  common "e"  /  del "d"
```

单独把 `del "r"` 推到对面，结果变成 `"rblu"` 或 `"blur"` —— **没有任何语义**。
用户眼里「一处改动」是相邻的 del/ins 合起来，所以细粒度单位必须是**替换组**。

### 3.2 切组算法的演进（3 稿都失败过，记录在此避免重蹈）

| 稿次 | 规则 | 失败现象 |
|---|---|---|
| 1 | 见 common 就断组 | `red→blue` 切出 2 组，各自推都不对 |
| 2 | 公共段长度 ≥ 12 才断 | 同上（那个 `e` 只有 1 字符） |
| 3 | 公共段含换行才断 | 仍不对：B 侧的 common 片段会把后续整行吞进组里 |
| **4（现行）** | **按行配对 + 公共前后缀裁剪** | ✅ 正确 |

**关键实测数据**（第 3 稿失败的原因）：

```
0 a common(15) "const color = \""
2 a del "r"
3 b ins "blu"
4 a common(1)  "e"                          ← A 侧只有 1 字符
5 b common(31) "e\";\nconst size = 10;"      ← B 侧同一处却是 31 字符，横跨到下一行
6 a del "d"
```

两侧的 common 片段长度**完全不对称**（1 vs 31）。
任何「按片段 / 按长度阈值」的切法都无法把组范围算对 —— 会把后续行吞进来。

### 3.3 现行算法

```ts
// core.ts
export function groupInline(pieces, chunkA, chunkB, textA, textB): InlineGroup[] {
  // 1. 取该 chunk 的 A/B 两侧文本
  // 2. 按行切分（保留行尾换行符，保证拼回原文）
  // 3. 行数不一致 → 退化成整块一组（纯增删行，不做 1:1 猜测配对）
  // 4. 逐行配对，用「公共前缀 + 公共后缀」裁剪出中间真正变化的区间
}
```

每行组范围 = `该行去掉公共前后缀后剩下的中间段`，两侧必然一一对应。

### 3.4 交互

1. 打开「行内」开关 → 每行标出红色（仅左侧有）/ 绿色（仅右侧有）片段
2. 点某个片段 → 选中它所属的**整个替换组**（金色描边）
3. 中间栏出现两个金色箭头 → 只推这一组
4. 再点同一片段 = 取消选中

## 4. 折叠：库的 `StateField.init` 限制

### 4.1 问题

`@codemirror/merge` 把折叠范围算在 `StateField.init` 里：

```js
// merge 源码
const CollapsedRanges = StateField.define({
  create(state) { return Decoration.none; },   // ← 只在 State 创建时执行
  update(deco, tr) { /* 只做过滤，不重算 */ }
});
```

后果：**文档内容一改，折叠范围就过期**；`reconfigure` 只换扩展、不重跑 `init`。
且 `collapseUnchanged` **未导出**，无法塞进 Compartment 手动重算。

### 4.2 试过的方案

| 方案 | 结果 |
|---|---|
| `reconfigure({ collapseUnchanged })` | 不重算，旧折叠范围保留 |
| 每次内容变化就重建 MergeView | **不可接受**：DOM 被换掉 → 丢焦点，用户无法连续输入（实测打字后焦点落到 `<body>`） |
| **内容变化不重建 + 手动「重折叠」按钮** | ✅ 采用 |

### 4.3 现行策略

折叠只在两处重算：

1. **折叠开关切换** —— 用户主动操作，丢焦点可接受；
2. **点工具栏「重折叠」** —— 内容改动后想让折叠跟随，点一下。

> 为什么可以「不自动重算」：merge 自己在 `CollapsedRanges.update` 里会把
> **与变更块重叠的折叠**过滤掉，所以不会出现「改动被藏起来」的情况，
> 最多是折叠位置暂时不理想。

## 5. 双向互推

`revertControls` 的类型是单向的：

```ts
revertControls?: "a-to-b" | "b-to-a";   // 一次只能选一个方向
```

且 `revertChunk` 内部是 `revertToA` 布尔值。所以改为**自绘中间栏**：

| 层级 | 按钮 | 行为 |
|---|---|---|
| 整块 | `⇥` / `⇤` | 用整块替换对面（`buildPush`） |
| 行内组 | 金色 `⇥` / `⇤` | 只替换选中的那一组（`buildGroupPush`） |

按钮位置通过 `view.a.lineBlockAt(chunk.fromA)` 的 `top` 计算，用 rAF 合帧，
且只渲染视口附近的 chunk（避免几千个 chunk 时插几千个 DOM）。

## 6. 踩坑清单（全部有实测证据）

| # | 坑 | 现象 | 修法 |
|---|---|---|---|
| 1 | `inlineDiff` 在 `a === b` 时只返回 a 侧片段 | 往返断言右侧为空 | 两侧各返回一段 common |
| 2 | 片段合并只用 `pieces[last]` 比较 | 产出逐字碎片，永远合不上 | 按侧各记一个游标 `tail[a/b]` |
| 3 | 组范围用「触发边界时的游标」 | 把下一处未改动内容整段吞进组 | 左右各记 `endA/endB`，共用一个回退量会算错 |
| 4 | 公共片段长度按两侧累加 | 阈值被算成两倍，同一处改动被判成两处 | 只按 a 侧累计 |
| 5 | `domEventHandlers({ mousedown })` 拾取行内片段 | CodeMirror 先消费事件，点不动 | 改挂**编辑器外层容器** + 捕获阶段 |
| 6 | `rAF` 守卫写成 `if (rafRef.current) return` | cleanup 后句柄未清零 → 后续调用**永久短路**，按钮再也不出现 | 每次覆盖句柄，只保留最后一帧 |
| 7 | 行内标记 effect 依赖漏了 `mountSeq` | **开发环境偶发可用、生产构建永远没有行内标记** | 补 `mountSeq` 依赖 |
| 8 | StrictMode 下 `mount` 执行两次不 destroy | 旧 EditorView 仍在监听 → 打一个字写入两三次（`XYZlXYZXYZine`） | 先 `destroy()` 再清 DOM |
| 9 | `selfEdit` 只清一侧 | 另一侧旧值残留 → 误判为外部写入，重复插入 | 每侧独立记录、用完置 `null` |
| 10 | 每次内容变化重建视图 | 丢焦点，无法连续输入 | 见 §4.3 |

## 7. 性能护栏

最坏情况（两份完全不同的随机行）实测 `Chunk.build()`：

| 行数 | 默认 | 无保护 |
|---|---|---|
| 2,000 | 1 ms | 1,234 ms |
| 10,000 | 2 ms | **36,781 ms** |
| 30,000 | 2 ms | — |

**结论**：必须显式传 `diffConfig: { scanLimit: 500, timeout: 400 }`。
代价是超大差异会退化成「整块」，此时 UI 显示「差异过大，已降级为粗略」提示。

另测 3.5 MB 单行 minified JSON：加 `scanLimit` 后 **1 ms**，无风险。

## 10. 明确不做

- 文件拖拽打开 / 另存为（用户明确「暂时不需要文件功能」）
- 三窗格合并（Beyond Compare 的 3-way merge）
- 语法高亮按语言切换（当前纯文本，避免加载 `lang-json` 等语言包）
- 编辑历史（多步撤销）—— 当前是单步快照撤销
