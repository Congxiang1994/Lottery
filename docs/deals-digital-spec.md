# 捡漏 · 数码垂类筛选规格（v1，2026-11-06）

> 状态：**已实施**。取代 2026-10-29 的「全品类 + 折扣优先」判据。
> 背景与实测数据见 [deals-sourcing-research.md](./deals-sourcing-research.md) 与本文件 §1。
> 面向实现的取舍见 §6「为什么这么做」。

## 1. 为什么改（7 天生产数据，2026-10-29～11-05）

改造前（全品类 + 折扣优先）的入选结构：

| 指标 | 实测 | 结论 |
|---|---|---|
| 入库 → 入选 | 5,953 → 1,141（19%） | 一天 163 条，噪音大 |
| 到手价中位数 | **67 元** | 一半不到 70 块 |
| < 50 元 | 489 条（43%） | 低单价占近半 |
| < 20 元 | 230 条（20%） | 五分之一是 20 块以下 |
| 食品生鲜 | 679 条（**59%**） | 品类高度集中 |
| 电脑数码 | 16 条（**1.4%**） | 想要的几乎没有 |

根因不是阈值，是判据维度错位：

1. **判定只看「折得多不多」，不看「值多少钱」** —— 19 元茶礼盒 1.5 折与 2300 元空调 1.1 折同权。
2. **数码两品类 94% 没有折扣数据**（46/928）、**92% 没有投票** —— 现有判据的两个输入在这里几乎全空。
3. **88% 的数码供给来自榜单源**（828/928），而榜单卡片既无原价也无值/收藏 → 全被拒。

## 2. 范围

只保留 **电脑数码 + 数码配件**，其余品类不入选。

抓取层**不变**：仍抓 4 个标签流 × 2 页 + 首页 1 页 + 榜单每 3 轮一次。
理由：判定层过滤即可，砍抓取会让「以后想加回某品类」需要重新调抓取节奏；且非数码条目落库后仍可用于 `cate_stats()` 观察供给结构。代价是库里继续存 `picked=0` 的非数码行，由 7 天保留期自然清理。

## 3. 判定规则（按执行顺序）

### 3.1 模式开关

`filter_mode` = `digital`（默认）| `legacy`。
`legacy` 完全退回 2026-10-29 的判定式，用于「看效果不满意」时一键回滚，不需要改代码。

### 3.2 品类

`cate1 ∈ cate_allow` 或 `cate2 ∈ cate_allow`，默认 `cate_allow = 电脑数码,数码配件`。

实测 98% 的数码条目 `cate1` 就是「电脑数码」，`cate2` 基本为空；两处都匹配是防站点改层级。

### 3.3 硬否决

| 规则 | 说明 |
|---|---|
| 非商品词 | 会员 / 年卡 / 月卡 / 兑换券 / 优惠券 / 代金券 / 流量 / 宽带 / 话费 / 课程 / 学习机 / 安装服务 / 延保 / 网盘 / 云盘 / SVIP / VIP |
| 活动帖词 | 清单 / 汇总 / 合集 / 攻略 / 日历 / 预告 / 焕新季 / 购物节 / 至高 |
| 价格无效 | 到手价解析为 0 或空（券帖、公告、纯文字帖）——实测 3 条 |
| 品类黑名单 | 沿用 `cate_blacklist`（在 digital 模式下已是冗余，保留以兼容 legacy） |

### 3.4 入选信号（满足其一）

| 档 | 触发位置 | 词表（`signal_t1` / `signal_t2`）|
|---|---|---|
| **T1 真漏** | `feed_tags` **或** 标题 | 绝对值 / 历史低价 / 手慢无 / 新低 / 直降 / 清仓 / 低价 |
| **T2 补贴** | 标题 | 百亿补贴 / 国家补贴 / 国补 / 一键补贴 / 京东超补 / 超级补贴 / 补贴 |

两者都没有 → 不入选（榜单里 89% 属于这类）。

T1 先于 T2 判断：同时命中时按 T1 计（信号更强）。

### 3.5 评分与排序

```
value = 价格档 × 信号权重 × 品牌系数

价格档    <50 → 0.3   50–200 → 0.6   200–1000 → 1.0   >1000 → 1.2   （0 元 → 0）
信号权重  T1 → 1.0    T2 → 0.8
品牌系数  命中 brand_allow → 1.3，否则 → 1.0

排序：value DESC → 到手价 DESC → first_seen DESC
```

⚠️ **T1 不等于「一定排在 T2 前面」**：公式是乘法，价格档跨 4 倍（0.3→1.2），
信号权重只差 1.25 倍。所以 258 元的手慢无配件（0.6×1.0 = 0.6）会排在
14,049 元的国补大件（1.2×0.8 = 0.96）之后 —— 这是**设计如此**：榜单要的是
「值得买的东西」，不是「信号词最漂亮的条目」。同价同品牌时 T1 才必然压过 T2。

**不设价格地板**：5 元钢化膜、25 元充电器照收，只是分数低、排在后面。
**不合并同款**：同型号多颜色/多容量/多帖子各占一条（用户 2026-11-05 明确选择）。

## 5. 实现落点

| 文件 | 改动 |
|---|---|
| `backend/app/smzdm/config.py` | 新词表、品牌表、价格档、权重、`DEFAULT_SETTINGS` 新键 |
| `backend/app/smzdm/store.py` | `judge()` 分支到 `_judge_digital()`；新增列 `value_score` / `signal_tier` / `price_num`；`list_deals()` 换排序；`init()` 一次性迁移触发全库重算 |
| `backend/app/smzdm/router.py` | `_validate_config` 接受新键；`stats()` 下发模式与词表供空态使用 |
| `frontend/src/deals/api.ts` | `Deal` 增三字段；`DealStats` 增模式字段 |
| `frontend/src/deals/Deals.tsx` | 折扣 chip → 信号 chip；副标题/统计条/空态文案 |
| `frontend/src/deals/DealsAdmin.tsx` | 筛选模式切换 + 词表编辑 |

**列而不是每次查表**：`value_score` / `signal_tier` 落库，理由同 `cate_hit` —— 列表查询不重新解析配置与正则。代价是改配置必须走 `rejudge()` 重算，这与现有 `update_settings → rejudge` 链路一致。

### 5.1 迁移

`init()` 用 `INSERT OR IGNORE` 抢 `digital_v1` 标记（`rowcount == 1` 的 worker 负责重算），在 `flock` 之外调用 `rejudge()`。多 worker 并发只有一人重算，重复执行幂等。

## 6. 为什么这么做（实现取舍）

1. **为什么不砍抓取**：抓取节奏调到 10 分钟/轮是压延迟换来的（见 config.py 注释），砍来源会重新引入「发布→进库」的延迟问题；而判定层过滤成本几乎为零（0.83ms 级别）。
2. **为什么信号词而不是分类标签**：站点已经在 `feed_tags` 里打了「绝对值/历史低价/手慢无」，这是编辑+值友双重筛选的结果，比我们自己用投票数猜更可信。
3. **为什么价格档是分段而不是连续函数**：用户扫列表只需要知道「这是不是大件」，不需要精确到元；分段也便于在管理页解释「为什么这条排前面」。
4. **为什么保留 legacy 模式**：这是「先看看效果」的需求，一键回滚的成本远低于重新发版。

## 7. 已知残留（接受或后续处理）

1. **同款重复**：机械革命两帖、iPhone 多色多容量相邻出现 —— 已明确不合并。
2. **活动帖漏网**：靠 §3.3 词表挡，词表需边跑边补。
3. **补贴 ≠ 史低**：百亿补贴只代表渠道，不代表真便宜。要判断「1,022 的 AirPods Pro 3 值不值」需要 30–90 天价格历史（P1，未做）。
