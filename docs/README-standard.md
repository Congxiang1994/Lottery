# README 编写规范

> 本文件是**仓库内所有 README 的唯一风格标准**。适用于根目录 `README*.md` 与
> `tools/*/README.md`。改 README 前先读这里；检查脚本见
> [scripts/audit-readmes.py](../scripts/audit-readmes.py)。

## 一句话原则

**README 是门牌，不是档案柜。** 30 秒内让读者知道「这是什么、在哪、怎么用、出问题去哪查」；
实现细节、踩坑记录、实测数据、决策过程一律放进链接指向的下一层文档。

## 文档分层（三层嵌套）

```
README.md                     第 1 层：全站总览（产品矩阵 / 快速开始 / 文档导航）
  ├── README_<module>.md      第 2 层：单个产品的门牌（本规范的重点）
  │     └── docs/modules/<module>.md   第 3 层：该产品的完整实现细节（原 README 全文）
  ├── docs/architecture.md    第 3 层：架构与扩展规范
  ├── docs/frontend-standards.md
  ├── docs/deployment.md
  └── docs/*-design.md / *-research.md  设计稿、实测报告
```

- 第 2 层**只放重要信息**，目标 40~70 行。
- 第 3 层 `docs/modules/` 保留历史全文，**不删细节、不改口吻** —— 需要追溯决策
  和踩坑时点进去看。
- 已有的独立设计稿（`docs/*.md`）继续作为第 3 层，不复制内容，只做链接。

## 第 2 层模板（所有模块 README 必须严格遵守）

```markdown
<!-- 示例：链接按「模块 README 位于仓库根」书写；xxx 为占位符 -->
# <emoji> <产品名> · <一句话定位>

> <2 行以内说明：解决什么问题 / 给谁用>。
> 全站总览见 `README.md`（链接写法见下方说明）。

## 速览

| 项 | 值 |
|---|---|
| 入口 | `/xxx` · [在线访问](https://doudoutech.cloud/xxx) |
| 前端 | `frontend/src/xxx/` |
| 后端 | `backend/app/xxx/` |
| 数据 | `<库/文件/目录>` |
| 鉴权 | 公开 / 全站操作密码（cookie `xxx_session`）/ `X-API-Key` |
| 外部依赖 | <第三方站点/服务/二进制>，无则写「无」 |

## 要点

- 3~6 条，每条一行半以内：只写「不看源码就不知道、且会影响使用/排障」的事实
- 用 **加粗** 标出关键词，不写长段落
- 不复述速览表里已有的信息

## 接口速查        ← 无接口的产品改为「配置速查」或「命令速查」

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/xxx/list` | 一句话 |

只列**最常用的 3~6 条**；全表见深入阅读链接。

## 深入阅读

- `实现细节（完整版）` → `./docs/modules/<模块>.md`：架构、数据表、踩坑、验收记录
- `相关设计稿` → `./docs/<模块>-design.md`（若有）
- `架构规范` → `./docs/architecture.md`、`前端规范` → `./docs/frontend-standards.md`
```

### 硬规则

| # | 规则 | 理由 |
|---|---|---|
| 1 | 一级标题只写产品名，不写文件名（`README_x.md —` 禁止） | 文件名在页面上已有，重复占标题 |
| 2 | 章节顺序固定：**速览 → 要点 → 接口/配置速查 → 深入阅读** | 跨模块扫读时位置可预测 |
| 3 | 不使用 `## 1. / ## 2.` 数字编号 | 与根 README 的无编号风格不一致，且插章节要重排 |
| 4 | 表格优先于段落；单段不超过 3 行 | 可读性 |
| 5 | 不写「需求背景 / 已确认决策 / 变更日志 / 验收清单」 | 这些是过程记录，属于第 3 层 |
| 6 | 所有相对链接必须能打开 | 由检查脚本强制 |
| 7 | 在线地址统一 `https://doudoutech.cloud/<path>` | 全站唯一域名 |
| 8 | 私有功能在标题下标注 🔒，速览「鉴权」行写明 cookie 名 | 与门户口径一致 |

## 第 1 层（根 README.md）的额外要求

根 README 允许有自己的结构，但必须包含四块，且顺序固定：

1. 站点定位（1 段 + 技术栈一行）
2. **产品矩阵**表（产品 / 一句话 / 文档链接）
3. **快速开始**（本地开发 + 部署各 1 个代码块）
4. **文档导航**（三层嵌套的入口表）

## 第 3 层（docs/modules/*.md）的要求

- 首行加一行 `> 本文是 <README_x.md> 的完整实现细节，由 README 拆分而来（保留历史全文）。`
- 其余内容**原样保留**，不要顺手重写 —— 它是可追溯的档案。

## 检查

```bash
cd <仓库根>
python3 scripts/audit-readmes.py
```

退出码 0 = 全部合规；1 = 列出违规文件与原因。检查项：模板章节、
标题格式、行数上限、链接有效性、分层文件存在性、速览表必需行。
